# DataAgent 准确性评估方案

> 目标：建立一套可落地、可持续的 DataAgent 准确性评价体系，支持离线评估、在线监控和人工反馈闭环。

## 1. 为什么要拆维度

DataAgent 的「准确性」不是单一指标。一次问答链条中可能出错的位置很多，必须拆开看，才能定位问题和迭代优化。

| 维度 | 核心问题 | 典型错误示例 |
|---|---|---|
| 意图理解 | 是否把用户问题翻译对了 | 用户问「最近一周销量」，理解成自然周还是近 7 天 |
| 数据查询 | SQL/指标/维度有没有取错 | 表名、字段、过滤条件、聚合粒度错误 |
| 分析推理 | 计算过程、归因、对比是否成立 | 同比环比公式错、异常归因因果倒置 |
| 结论表达 | 最终报告是否真实反映数据 | 数字和结论不一致、过度推断 |

面试时回答这类问题，先拆维度，再讲指标和落地，会显得更系统。

## 2. 评价体系：离线 + 在线

### 2.1 离线评估（上线前 / 定期回归）

#### Golden Dataset（标准答案集）

- 准备 50~200 条覆盖不同业务场景和数据难度的问题
- 每条包含：用户问题、期望 SQL、期望结果、期望结论
- 定期全量跑一遍，统计：
  - SQL 执行成功率
  - 结果一致性（行级 diff、数值 diff）
  - 结论匹配度

#### SQL/指标正确率

- SQL 生成后能否直接执行通过
- 执行结果与标准答案的差距
- 字段、维度、过滤条件是否与预期一致

#### LLM-as-Judge

- 用另一个模型判断主 Agent 的结论是否合理
- 与本项目已有的「双 Agent 复核」机制思路一致

### 2.2 在线评估（真实运行中）

#### 执行成功率 / 报错率

- SQL 生成后执行失败的占比
- 直接反映数据查询层的稳定性

#### 用户反馈

- 点赞/点踩
- 是否重新提问、是否继续追问
- 用户对报告是否满意

#### 人工抽检

- 每周/每月抽 N 个会话
- 人工标注：正确 / 部分正确 / 错误
- 建立错误分类标签：意图错误、SQL 错误、推理错误、表达错误

#### A/B 实验

- 换模型、换 prompt、换工具时，对比准确率和用户满意度
- 避免凭感觉上线

## 3. 在本项目中的落地方案

### 3.1 复用并扩展「复核 Agent」为后台评估器

当前项目已实现 `review_graph` + `compare_reports`，目前作为 UI 上的「复核」按钮触发。可以把它扩展为后台评估 pipeline：

```
主 Agent 生成报告
    ↓
复核 Agent 独立重跑同一问题
    ↓
compare_reports 输出 verdict + differences
    ↓
保存到 evaluation 表 / 日志 / 看板
```

用户每次主动点击复核，都在贡献评估数据。

### 3.2 增加 Golden Dataset 评估任务

在 `evaluation/` 目录下新增一个可独立运行的脚本：

```bash
python -m evaluation.golden_eval --dataset evaluation/golden_questions.jsonl
```

流程建议：
1. 读取标准问题集
2. 对每个问题调用主 Agent（复用现有 API）
3. 拿到 SQL 和报告
4. 执行 SQL 并与标准 SQL 做 diff
5. 用 LLM 判断结论是否一致
6. 输出准确率、错误 breakdown

可作为 CI 环节，每次修改 prompt 或工具后自动跑一遍。

### 3.3 建立准确性看板

当前已有 `thread_reviews` 表存储复核结果。在此基础上可扩展：

| 表 | 作用 |
|---|---|
| `eval_runs` | 每次评估运行的元信息 |
| `eval_results` | 每个问题的评估结果 |
| `human_labels` | 人工标注结果 |

看板可以关注：
- 复核一致率：consistent / partial / inconsistent 占比
- 高频错误类型
- 准确率随时间变化趋势

### 3.4 用户反馈闭环

在报告或复核弹窗旁增加反馈入口：

- 「这个结论对吗？」
- 「数据有问题」→ 让用户指出哪一列/哪一行错了

把反馈和当时的 `thread_id`、`review_id` 一起落库，定期 review。

### 3.5 推荐落地顺序

不要一开始追求完美指标，按以下节奏推进：

1. **先跑起来**：把复核 Agent 的 verdict 和 differences 落库，能看分步
2. **再加 golden set**：挑选 50 个高频问题，人工写好标准答案，定期自动跑
3. **再做人评**：每周抽 20 个真实会话人工标注
4. **最后做看板**：把上述数据汇总，成为团队周报的固定部分

## 4. 面试收尾话术参考

> 评价 DataAgent 准确性，我会把它拆成「意图理解—数据查询—分析推理—结论表达」四层，分别用离线 Golden Dataset、LLM-as-Judge、在线执行成功率、用户反馈和人工抽检来评估。在我们这个项目里，我会优先把已有的双 Agent 复核机制扩展成后台评估 pipeline，把 verdict 和差异点持久化，同时建立 golden set 和人工抽检机制，最后通过看板持续追踪。
